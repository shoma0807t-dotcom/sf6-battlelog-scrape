# sf6-battlelog-scraper

「スト6攻略ノート」アプリの対戦履歴を自動取り込みするための、GitHub Actions用スクレイパーです。
ログイン中のブラウザからコピーした**セッションCookie**を使って対戦履歴APIを直接叩き、
結果を**GitHubのGist（非公開）**にアップロードします。

> **補足：** 一時期、CAPCOM IDのメール・パスワードでヘッドレスブラウザ（Playwright）から
> 自動ログインする方式を試しましたが、ログイン画面自体がBot対策（Cloudflare）にブロックされ
> 動作しませんでした。このCookie方式はブラウザ操作を一切行わず素の`fetch()`でAPIを叩くだけなので、
> そのブロックには引っかからず安定して動きます。

## 重要な注意点

- **Cookieはいずれ切れます。** 切れたら取得に失敗するので、下記の手順3を再度行ってSecretsを
  更新してください（頻度は未知数。数週間〜数ヶ月で切れる可能性があります）。
- **これは公式のAPIではありません。** サイトが内部で使っている非公開のデータ取得の仕組みを
  利用しているため、サイトの仕様変更で予告なく壊れる可能性があります。
- **Gistは「secret」＝限定公開です。** 完全非公開（認証必須）にはできません。
  URL（GistのID）を知っていれば誰でも中身を見られる、という扱いです。
- **Cookieを他人と共有しないでください。** ログインセッションそのものなので、漏れるとアカウントを
  乗っ取られます。GitHubのSecrets以外の場所（コード中への直書きなど）には絶対に置かないでください。

## 仕組み

1. GitHub Actionsが `SF6_SESSION_COOKIE` をAPIリクエストのヘッダーに乗せて対戦履歴を取得する
   （直近100戦分。公式サイト側がそれ以上を保持していないための制限）
2. **差分取得：** 先に既存Gistの中身（前回までの蓄積）を確認し、ページを取得するたびに
   「そのページの中身が全部既知のreplay_idだったら、そこで打ち切る」ようにしている。
   毎回100件フルで取り直すのではなく、新しい対戦が出てきた分だけ取りに行く
3. `replay_id`（対戦ごとのユニークID）を主キーとして、既存のGistの中身と突き合わせて
   新しい対戦だけを追加していく（＝Gistの中身が蓄積されていく）
4. `GIST_TOKEN` を使って、Gist（`GIST_ID`）の2つのファイルを更新する：
   - `battlelog.json` … アプリが読み込む、蓄積済みの対戦履歴（data）
   - `battlelog-raw.json` … 今回の実行で実際にAPIから返ってきた生レスポンス（raw、デバッグ用）
5. アプリ側の「マイページ」の戦績にある「🔄 戦績データを更新」（＝ここまでの1〜4を実行するだけ）と
   「⬇ 戦績を取り込む」（＝Gistの中身をアプリに取り込む）は別ボタンです。
   更新しただけではアプリには反映されないので、数分待ってから「取り込む」を押してください。

**エラー・レート制限への対応：**
- リクエストごとに `SF6_REQUEST_DELAY_MS`（デフォルト400ms）だけ間隔を空ける
- `429`（レート制限）・`5xx`（サーバーエラー）は指数バックオフで最大3回リトライ
- `401`（認証切れ）・`403`（アクセス拒否）・`404`（URL不正）は即座に諦めて、原因が分かる
  メッセージでエラー終了する（無駄にリトライして状況を悪化させない）

> **なぜSQLiteではなくJSON？** GitHub Actionsは状態を保持できない（毎回まっさらな仮想マシン）ので、
> どこかに外部保存する必要があります。今回はGist（テキスト前提の仕組み）に保存する設計にしたため、
> バイナリのSQLiteより素直に扱えるJSONにしました。`replay_id`を主キーにして重複なく蓄積する、
> という狙いはJSONでもそのまま実現できています。

## セットアップ手順

### 1. このフォルダの中身でリポジトリを作る
GitHubで新しい**プライベートリポジトリ**を作成し、このフォルダ一式をpushしてください。

### 2. 自分のプレイヤーID（fighter ID）を確認する
プロフィールページURL末尾の数字です（例：`1229292585`）。

### 3. セッションCookieを取得する
1. 普段使っているブラウザで `https://www.streetfighter.com/6/buckler` を開き、CAPCOM IDでログインする
2. 開発者ツール（Windows: F12 / Mac: Cmd+Option+I）を開き、「Network」タブを選ぶ
3. ページをリロードし、`streetfighter.com` 宛のどれかのリクエストをクリック
4. リクエストヘッダーの中の `Cookie` の値を丸ごとコピーする（`cid_xxx=...; cid_yyy=...` のような文字列）

### 4. Gistを1つ作っておく
1. https://gist.github.com を開く
2. ファイル名を `battlelog.json`、中身は `[]` とだけ入力
3. 右下の「Create secret gist」をクリック（**public gistではなくsecret gistを選ぶこと**）
4. 作成後のURL末尾の英数字列が **GIST_ID** です

### 5. Personal Access Tokenを作る（Gist更新用）
1. https://github.com/settings/tokens (classic) を開く
2. 「Generate new token (classic)」→ スコープは **`gist`のみ** にチェック
3. 生成されたトークンが **GIST_TOKEN** です（一度しか表示されないので注意）

### 6. GitHub Secretsに登録する
リポジトリの Settings → Secrets and variables → Actions → New repository secret で、以下4つを登録：
- `SF6_SESSION_COOKIE` … 手順3のCookie文字列
- `SF6_FIGHTER_ID` … 手順2のプレイヤーID
- `GIST_TOKEN` … 手順5のトークン
- `GIST_ID` … 手順4のGist ID

### 7. 実行してみる
Actionsタブから `Scrape SF6 battlelog` を手動実行（workflow_dispatch）してみてください。
成功すると、手順4で作ったGistの `battlelog.json` が更新されます。

### 8. アプリに取り込む
アプリの「設定 → 対戦履歴の取り込み設定」の②に、以下の形式のURLを一度入れて取得しておくと、
以降は「マイページ」の「⬇ 戦績を取り込む」ボタンから直接取り込めるようになります：

```
https://gist.githubusercontent.com/あなたのユーザー名/GIST_ID/raw/battlelog.json
```
